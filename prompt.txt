Build a decentralized file-sharing system for a college LAN network, in Python.

TECH STACK (strict):
- Backend: Flask (Python)
- Frontend: HTML + CSS (custom, no Bootstrap) — dark, minimalist, CRED/Spotify-inspired UI 
  (deep black/charcoal background, one vibrant accent color like neon green or electric purple, 
  bold rounded sans-serif typography, card-based layout, smooth hover states, generous spacing)
- Optional: Streamlit for an internal admin/debug dashboard only (not the main user-facing UI)
- No JavaScript frameworks (React/Vue) — vanilla JS only if needed for progress bars/polling
- Database: SQLite (simple file-based, no setup needed)

ARCHITECTURE:
1. TRACKER (Flask server, runs once on any machine on the LAN):
   - Maintains a registry of files: filename, file_hash (SHA-256), file_size, 
     list of chunk hashes (split file into 256KB chunks), list of peer IPs seeding each file
   - Endpoints:
     - POST /register_peer — peer announces itself with its IP and port
     - POST /upload_metadata — peer uploads file metadata + chunk manifest after adding a file
     - GET /files — list all available files with metadata
     - GET /peers/<file_id> — return list of peer IPs/ports that have pieces of this file
     - POST /peer_has_chunk — peer reports it has downloaded and verified a specific chunk 
       (updates tracker's peer-chunk map so it can be a source for others)

2. PEER NODE (Flask app, runs on every student's machine, acts as both client and mini-server):
   - On startup: registers itself with the tracker
   - Has its own small Flask server exposing:
     - GET /chunk/<file_id>/<chunk_index> — serves a specific chunk of a file it has, 
       to other peers who request it
   - To download a file:
     - Ask tracker for file's chunk manifest + list of peers
     - For each chunk, pick a peer (round robin or random) that has it, 
       fetch chunk via HTTP GET to that peer's /chunk endpoint
     - Verify chunk against SHA-256 hash from manifest
     - Once verified, save chunk locally, reassemble file when all chunks received
     - Report back to tracker "I have chunk X" so it becomes a source for other peers too
   - To upload/seed a file:
     - Split file into 256KB chunks, compute SHA-256 hash per chunk and for whole file
     - Upload manifest to tracker
     - Keep local Flask server running to serve chunks on request

3. FRONTEND (served by peer's Flask app, single-page feel using Flask templates + fetch polling):
   - Landing/home page: shows list of files available on the network as CARDS 
     (like Spotify's "browse" grid) — each card shows filename, size, number of active seeders, 
     a subtle progress ring if currently downloading
   - Upload page: drag-and-drop zone (styled like CRED's clean upload states) to seed a new file
   - Download progress view: real-time (polling every 1s) progress bar per file showing 
     "X% complete, fetching from N peers" with peer count animating like a live counter
   - Use CSS variables for theming (--bg-primary: #0d0d0d, --accent: #7c3aed or similar), 
     custom fonts (Inter or similar via Google Fonts), smooth CSS transitions on hover/click, 
     rounded corners (12-16px), subtle box-shadows for depth like CRED's card elevation

FOLDER STRUCTURE:
/tracker
  app.py          # Flask tracker server
  models.py       # SQLite schema for files, chunks, peers
/peer
  app.py          # Flask peer node (client + chunk server combined)
  swarm.py        # chunking, hashing, download/upload logic
  templates/
    index.html    # file browser (Spotify grid style)
    upload.html   # drag-drop upload
    download.html # progress view
  static/
    style.css     # CRED/Spotify dark theme
    script.js     # polling for progress updates
/shared
  utils.py        # SHA-256 chunking/hashing helpers shared by tracker and peer

BUILD ORDER (do this step by step, test each before moving on):
1. Scaffold folder structure and shared chunking/hashing utility functions first
2. Build tracker Flask app with SQLite models — test with Postman/curl before UI
3. Build peer Flask app's chunk-serving endpoint — test peer-to-peer chunk fetch manually
4. Build peer's download logic (fetch manifest, fetch chunks from multiple peers, verify, reassemble)
5. Build peer's upload/seed logic (chunk + hash + register with tracker)
6. Build the CRED/Spotify-style frontend last, once backend logic is proven working via CLI/curl
7. Add polling-based progress bars using vanilla JS fetch() calls every 1 second to a 
   /progress/<file_id> endpoint

DEMO REQUIREMENTS TO KEEP IN MIND WHILE BUILDING:
- Must work with tracker and 3+ peer instances running on localhost with different ports 
  (simulating multiple students) for local testing before real LAN demo
- Killing one peer mid-download should not stop other peers from completing the download
- Include a simple seed script that generates 2-3 dummy files pre-seeded so the demo 
  has content immediately without manual setup
